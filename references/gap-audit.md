# 盤點缺口與補齊順序

使用者問「元件齊了嗎」「哪些風格還沒補」「把不足的補齊」時，照這份做。目標是交出一張**分好類、排好順序**的清單，等使用者點頭再動手。

## 1. 先看總表，但不要只看總表

總表上的「用基本款」不一定代表缺。可能是：

- 設計上本來就沿用基本款（刻意的）；
- 這個風格已經用樣式檔改過外觀，只是沒有專屬元件；
- 真的還沒做。

要分辨，得回頭看設計稿。

## 2. 設計稿要全部查過

設計稿常常分散在好幾種檔案：元件包（元件總表）、各頁畫板、補充說明。**一個物件可能沒出現在元件包，卻畫在某一頁的畫板上。**

做法：

1. 用物件的中文名稱、英文名稱、畫面上的字（例如按鈕上的「早報」）去搜尋**所有**設計檔，不只元件包。
2. 找到後記下：畫在哪個檔、哪一段；有沒有指定「放在哪裡」（例如「區塊結尾」「晚上的首頁右下角」）。
3. 在回報裡寫出查過哪些檔。說「沒畫」之前，一定要能說出查了哪裡。

查錯的代價很高：說「沒畫」會讓使用者以為要先補設計，其實只差寫程式。

## 3. 把缺口分成四類

| 類別 | 判斷方式 | 怎麼處理 | 先後 |
|---|---|---|---|
| 做了沒用 | 總表「還沒有地方使用」，設計稿有指定位置 | 照設計稿的位置放進畫面 | 最先：成本最低、立刻看得到 |
| 有設計、沒程式 | 設計稿畫了這個風格的版本，程式用基本款或只換了顏色 | 照設計稿實作專屬元件 | 第二 |
| 連設計都沒有 | 設計稿查遍都沒有這個風格的版本 | 先請使用者補設計，不要自己發明外觀 | 等設計 |
| 有素材、沒位置 | 設計稿有畫物件，卻沒說要放在哪 | 建議先不做，做了只會多一批沒人用的素材 | 暫緩 |

位置沒指定的大型裝飾（例如背景角落的大圖案）也算「沒位置」，要先在設計稿決定擺在哪、會不會擋到按鈕。

## 4. 回報格式

```
## 缺口盤點

查過的設計檔：<列出>

### 做了沒用（建議先做）
- <物件>：<哪些風格>，設計稿指定 <位置>（<檔名>）

### 有設計、沒程式
- <物件>：<哪些風格>，設計見 <檔名>

### 連設計都沒有（要先補設計）
- …

### 有素材、沒位置（建議先不做）
- …

建議順序：…
```

接著問使用者要從哪一批開始。

## 5. 動手補的時候

- 放位置之前，先列出「哪個風格的哪個物件放在哪一頁的哪個位置」給使用者確認。裝飾類元素放錯位置很容易顯得花俏。
- 一個位置只放一個裝飾。已經有別的東西在同一處，就取代或不放，不要疊上去。
- 純裝飾的圖示要讓螢幕報讀軟體略過（例如加 `aria-hidden="true"`）。
- 和設計稿不一致的地方（因為既有規則或技術限制），在回報裡逐條寫出來。
- 補完重新產生總表，確認對應的格子變成「專屬」、「還沒有地方使用」消失。
