# component-catalog：讓人和 AI 都找得到現成元件

這是一個給 Claude 用的 skill（技能包）。它幫網頁專案建立一套元件管理方式：每個畫面物件只寫一份，自動產生一張「元件總表」，並讓 AI 做畫面前先查表、用現成的。

單一風格的網站、有多種主題或換膚的網站都適用。React、Vue、Svelte，或只有 CSS 的專案都能用。

## 它解決什麼問題

- **素材做了沒人用**：設計師畫好、工程師也寫好了，但做新頁面的人或 AI 不知道它存在，又自己畫了一份。
- **同一個東西到處各寫一份**：頭像、分隔線、「沒有資料」的畫面，每頁長得都有點不一樣。要改設計時，得一頁一頁找。
- **不知道還缺什麼**：哪個主題少了哪個元件，只能靠記憶。

## 它怎麼做

1. **每個物件一份共用介面，每種風格各一份實作**：頁面只寫一次 `<Avatar />`，換主題時外觀自動跟著換。某個主題沒有專屬版本，就自動用基本款。
2. **用腳本從程式碼自動產生總表**：手寫的清單一定會過時，所以總表由腳本產生。程式改了、總表沒重新產生，測試就會失敗。
3. **把規則寫進給 AI 的專案說明**：例如 Claude Code 的 `CLAUDE.md`，規則是做畫面前先查總表、用現成元件、找不到合適的先問人，不要自己新增。

## 總表長什麼樣

腳本產生的 `CATALOG.md` 開頭會有一張一覽表：

| 物件 | 基本款 | 森林 | 復古 | 使用處 |
|---|---|---|---|---|
| 頭像 `Avatar` | 專屬 | 專屬 | 專屬 | 1 處 |
| 分隔線 `Divider` | 專屬 | 專屬 | 用基本款 | 1 處 |
| 空狀態 `EmptyState` | 專屬 | 專屬 | 用基本款 | 1 處 |
| 點綴 `Sparkle` | 不畫 | 專屬 | 不畫 | **還沒有地方使用** |

- **專屬**：這個主題有自己的版本。
- **用基本款**：沒有專屬版本，自動用基本款。
- **不畫**：這個主題刻意不畫這個物件。
- **還沒有地方使用**：做好了卻沒放進任何畫面，是最該先處理的素材。

一覽表下面，每個物件各有一節：用途、每個主題的程式檔連結、目前用在哪些檔案。

只有一種風格的網站，表格只會有「物件」和「使用處」兩欄。

## 安裝

**Claude Code**：把 `component-catalog` 資料夾複製到 `~/.claude/skills/`（Windows 是 `C:\Users\<你的帳號>\.claude\skills\`）。

**claude.ai**：在技能設定上傳 `component-catalog.skill` 檔。

裝好後不用特別呼叫。你提到下面這類需求時，Claude 會自動使用它。

## 怎麼用

直接用平常的話說就好，例如：

| 你的情況 | 可以這樣說 |
|---|---|
| 開新專案，想先打好基礎 | 「我在做一個 React 部落格，之後想要日間和復古兩種主題，幫我把元件管理建立起來。」 |
| 舊專案元件很亂 | 「我們的元件越來越亂，有些做了沒人用，幫我盤點，先給我看結果再動手。」 |
| 想知道還缺什麼 | 「森林和復古兩個主題各還缺哪些元件？設計稿在 design/ 資料夾。」 |
| 已經導入，要做新頁面 | 照常請它做畫面就好，它會先查總表。 |

Claude 改動專案結構之前，會先說明要建哪些檔案、搬哪些元件。既有專案會先盤點，請你挑要先整理哪幾個，一次只搬幾個。

## 需要什麼

- **Node.js 18 以上**：總表腳本只用 Node 內建功能，不用安裝任何套件。
- **專案結構**：每個風格一個資料夾，每個物件一個檔案，例如 `src/ui/variants/base/Avatar.tsx`。Claude 導入時會幫你建好。

## 檔案內容

```
component-catalog/
├── SKILL.md                  給 Claude 的主要說明：四種情境的做法
├── scripts/catalog.mjs       總表產生腳本（加 --check 只檢查是否過期）
├── assets/
│   ├── component-catalog.config.example.json   設定檔範本
│   └── agent-rules.md                          貼進 CLAUDE.md 的規則範本
└── references/
    ├── stacks.md             React、Vue、Svelte、純 CSS 的寫法
    └── gap-audit.md          盤點缺口與補齊順序的做法
```

設定檔每個欄位的說明，寫在 `SKILL.md` 的「腳本」一節。

## 測試結果

我們用三個情境，分別讓 Claude 在「有這個 skill」和「沒有這個 skill」的情況下做同一件事，再逐項檢查結果：

| 情境 | 有 skill | 沒有 skill |
|---|---|---|
| 替新的 React 專案導入 | 6/6 | 1/6 |
| 盤點已導入專案的主題缺口 | 8/8 | 8/8 |
| 盤點單一風格的舊專案並提出計畫 | 8/8 | 6/8 |

沒有這個 skill 時，Claude 也會做共用元件，但清單多半是手寫的，不會自動產生，也不會接進測試，規則裡也少了「找不到先問」。第二個情境的專案本來就已經導入總表，所以兩組分不出差別。

## 限制

- 腳本只看檔案名稱和內容，不執行程式。物件必須一個檔案一個，檔名就是物件名稱。
- 「使用處」是用文字比對找出來的，例如找 `<Avatar` 或 `.Avatar`。用字串動態取用元件時會漏算，在設定檔的用途說明裡寫清楚取用方式即可。
- 只有 CSS、沒有元件框架的專案，「使用處」欄只能當參考。
- 專案結構特殊時可以修改腳本，但請保留兩個原則：總表從程式碼產生，過期時檢查會失敗。
